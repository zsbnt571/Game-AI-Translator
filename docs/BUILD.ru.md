# Сборка и исходные материалы — 1.1.127

[简体中文](BUILD.md) · [English](BUILD.en.md)

## Выберите нужный пакет

- **Fusion-1.1.127.zip** — полное готовое приложение.
- **Fusion-1.1.127-Source.zip** — полный архив исходников с соответствующими распространяемыми зависимостями, оригинальными лицензиями и материалами сборки.
- **Git и автоматические архивы Source code GitHub** не содержат полного набора бинарных зависимостей. Они подходят для просмотра кода и изменений, но не заменяют все входные материалы сборки.

Начинайте с полного архива той же версии. Не смешивайте старые компоненты и случайные DLL из игр. Первое восстановление NuGet может потребовать сеть. Полный архив не доказывает возможность полностью автономной сборки всех компонентов с нуля.

Собственный код сохраняет GPL-3.0-only; зависимости, модели и бинарные компоненты имеют свои условия. См. [сторонние компоненты](../THIRD_PARTY_NOTICES.md) и [исходники зависимостей](../third-party-source/README.md).

## Сборка настольного приложения

Основная среда — Windows x64. Приложение использует .NET 8; UnrealCatalog требует SDK с поддержкой .NET 10. Соответствующие старые помощники также используют ссылки разработчика .NET Framework 4.8 и Windows SDK 10.0.26100.0. У отдельных нативных мостов и плагинов собственные инструменты; успех основной сборки не доказывает их полную пересборку.

В корне с каталогами Source и tools выполните:

    powershell -ExecutionPolicy Bypass -File .\tools\Build-Desktop.ps1

Параметр -DotNet выбирает dotnet. Скрипт создаёт новый каталог Build и отказывается перезаписывать существующий. Историческое имя основного проекта — Source/Screenshot/ScreenshotTranslationUiTester.csproj; он создаёт GameTranslator.

Используются некоторые поставляемые готовые ресурсы адаптеров. Каждый плагин Unity, нативный мост, runtime и модель этим способом с нуля не перестраиваются. Побайтовая воспроизводимость и полная сборка на чистой машине не следуют из успеха основной сборки. Область проверок публичного пакета описана в [результатах](VALIDATION-1.1.127.md).

Для выпуска публикуйте приложение, помощник обложек и UnitySchema с `RuntimeFrameworkVersion=8.0.33`; скрипт также явно передаёт основному проекту `UnitySchemaRuntimeVersion=8.0.33`. Для UnrealCatalog используйте `RuntimeFrameworkVersion=10.0.14`. Параметры Restore и Publish должны совпадать. Обновление системной среды не обновляет автономный пакет. Среда .NET 10.0.14 готового инструмента GameMaker обслуживается отдельно в исходном и исполняемом пакетах без пересборки его прикладного кода. Старый загрузчик IL2CPP сохраняет .NET 6.0.7; замена на другую основную версию требует отдельной проверки совместимости.

Сначала скрипт собирает предварительные компоненты OCR, обложек и Yukar, затем публикует CoverCapture, UnitySchema и UnrealCatalog и только после них основное приложение. Восстановление и публикация ресурсов win-x64 для обложек должны завершиться до выполнения копирующих целей основного проекта. Повторная сборка помощников в основном проекте пропускается. `Build/Publish` содержит приложение, а `Build/Helpers` — три отдельных помощника. Полный пакет собирается по указаниям ниже.

## Ссылки Unity предоставляются локально

Публичные материалы не содержат пять ссылок компиляции из Source/Plugin/References: mscorlib.dll, System.dll, System.Core.dll, UnityEngine.dll и UnityEngine.UI.dll, а также игровые сборки. Происхождение первых трёх старых ссылок Mono не зафиксировано достаточно точно; оригиналы сохранены отдельно и не распространяются в публичных исходниках. При самостоятельной сборке соответствующих плагинов получите подходящие ссылки из разрешённого источника и оставьте локально. Не добавляйте их в Git или публичный архив.

Старый плагин поддерживает внешний каталог ссылок:

    $referenceDirectory = Read-Host 'Local compile-reference directory'
    powershell -ExecutionPolicy Bypass -File .\Source\Plugin\build.ps1 -ReferenceDirectory $referenceDirectory -OutputDirectory .\Build-local\LegacyPlugin

Каталог должен содержать требуемые ссылки framework, UnityEngine.dll, UnityEngine.UI.dll и BepInEx.dll. Скрипт принимает -DotNet и -SdkVersion для установленного совместимого компилятора.

Проект Mono6 предоставляет следующие свойства:

    $frameworkReferences = Read-Host 'Local framework and UnityEngine reference directory'
    $loaderReferences = Read-Host 'Local BepInEx Mono6 loader reference directory'
    dotnet build .\Source\Plugin\UnityEmbedded\FusionUnityMono6.csproj -p:FrameworkReferenceDirectory="$frameworkReferences" -p:LoaderDirectory="$loaderReferences" -o .\Build-local\UnityMono6

Свойства задают пути, не загружают ссылки и не дают права распространения. Остальные объявленные ресурсы проекта также необходимы.

У старого UnityEmbedded/build-mono.ps1 иная граница: -FrameworkReferenceRoot меняет только framework DLL, но не UnityEngine/BepInEx; Harmony использует фиксированный относительный путь. Это не полный выбор внешних ссылок Unity. Предоставляйте реально требуемые файлы только в личной копии сборки.

## Необязательные проверки и развёртывание

Две старые проверки макета читают внешние материалы только при явной установке FUSION_LAYOUT_FIXTURE_ROOT. Оригинальные игровые материалы публично не поставляются. Без разрешённых подходящих данных эти проверки нельзя считать выполненными. Обычный запуск и сборка в них не нуждаются.

Исследование локальных моделей описывает развёртывание внешнего сервиса. Настройка совместимого адреса не означает встроенную загрузку, обучение, управление сервисами или интеграцию всех упомянутых инструментов. Исследования Android и других платформ также не являются поставленной поддержкой.

## Сборка полного пакета

Результат компиляции не является автоматически готовым переносимым выпуском. Нужны соответствующие runtime, OCR/графические зависимости и модели, оригинальные лицензии, чистый относительный путь данных, актуальные документы и контрольные суммы. Личные настройки, ключи, заполненный кэш, сохранения, игровые ресурсы, проприетарные DLL распаковки Oodle и машинные журналы развёртывания исключаются.

Сохраняются сторонние лицензии и сведения об исходниках. В распространяемой копии BepInEx удалены две ссылки компиляции Unity, поэтому её хеш отличается от исходного ZIP разработчика; см. [навигацию по исходникам](../third-party-source/README.md). Хеш подтверждает идентичность файла, но не заменяет лицензию.
